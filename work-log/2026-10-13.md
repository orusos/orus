# 2026-10-13 — Debian track decisions

## Decisions

- Base: Debian stable, no desktop environment. Not Arch (rolling, image changes between builds); not Ubuntu (snaps, 6-month releases, Canonical patches).
- Shell: step 1 `orus-linux` as a Wayland client under `cage`; step 2 detir as the compositor (smithay) so Firefox is a real window.
- Dev: Debian aarch64 VM on the Mac, over SSH. UTM clipboard needs `spice-vdagent`; SSH avoids it.
- `br2-orus` (Buildroot, musl, Rune/Arth packages) is not reused for this track. It stays for Pi4/appliance. If revived: glibc, not musl (rusty_v8 prebuilts are glibc).

## Facts found

- `orus-universal/crates/orus-linux` is 62 lines: winit + `orus-shell` + `detir-scene`.
- `ORUS/compositor` is smithay 0.7, about 1,600 lines, GL renderer, targets Rune.
- `ORUS/br2-orus` Pi4 image was still a pending checklist (Jan 2026 docs).
- `detir-webview` Linux backend: WebKitGTK, X11 only, never built.
- `orus-sandbox`: brokers only, no OS isolation found.
- No Linux CI found in `detir` or `orus-universal`.

- VM set up: UTM 4.7.5, QEMU backend, virtualized, OpenGL acceleration on, 8 GB / 4 cores / 64 GB. Guest has `/dev/dri/renderD128`. Rust 1.99 and build deps installed; source rsynced to `~/src` on the guest.
- `cargo build -p orus-linux` fails at manifest load: `orus-universal` depends on `detir/crates/detir-wkwebview`, which does not exist (only `detir-webview`, different API).

- Linux build needed: gate `detir-webview` GTK behind a `gtk` feature (detir-scene depends on it unconditionally); drop orus-shell's WKWebView overlay (upstream removed `is_webview_mode`/`webview_url`); add Linux sans families in jag-draw (fontdb ignores fontconfig, default `Arial` misses).
- Debian runtime needs a font package (`fonts-noto-core` or `fonts-dejavu-core`); add as a Depends of `detir-shell`.
- VM GPU: Vulkan = llvmpipe only; GLES = virgl (host Apple GPU) but wgpu's EGL context creation fails (0x3009) and it uses llvmpipe.
- Frame under `cage`: `orus-linux` runs, window and chrome draw, Browser app content area looks partial.

- On the UTM console: `cage` + `orus-linux` runs fullscreen, the built-in terminal app runs, windows close. Upside-down pointer fixed by `WLR_NO_HARDWARE_CURSORS=1` (virtio-gpu cursor plane); launcher is `~/start-orus` on the VM.

- Web bundles: `file://` navigation passed the shell's `~/.orus/` policy only after moving the app to `~/.orus/apps/`. The embedded `SceneRenderer` then showed "Web load failed" because `poll` ignores `raw_html`. Standalone `detir-scene` (built on the VM, 7 min) rendered `react-shadcn-suite`; the shell now launches it per app. Confirmed on the UTM console: app window opens on top; media does not work.

## Decisions (later in the day)

- Apps: two modes. Shared runtime (web bundle under `~/.orus/apps/`, run by one `detir-scene`) is the Orus OS default; standalone (`waid build --target linux`, cargo-packager bundle with its own `detir-scene`) stays for other systems.
- Embedded `SceneRenderer` cannot render web bundles; the shell launches `detir-scene` per app instead.
- Compositor: labwc (wlroots, packaged in Debian) in place of `cage`, then the smithay compositor only if a detir-specific protocol is needed. Reasons: `ORUS/compositor` does not build (missing `rune-compositor`), lacks XWayland, foreign-toplevel, screencopy, text-input; a compositor is hard to make mature and is not the differentiator.
- labwc caveat: winit has no layer-shell, so the shell stays an ordinary window kept at the bottom by window rules.

- 2026-10-14: System Settings opened empty: its IR view fails the current schema (`computed_style`), as do Browser, Workflow Editor and Sim Viewer. Rebuilt Settings as a React app (`apps/system-settings`), launched through the waid app shell (`DETIR_WAID_APP_PATH`, needs `waid-package.json`). The app shell hung at startup on `dark_light::detect()` (D-Bus portal); `detir-scene` now times it out after 500 ms.
